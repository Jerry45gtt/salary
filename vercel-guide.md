# Размещение Salary на Vercel

## Подготовка

Проект использует Next.js и предназначен для Node.js runtime. Перед публикацией проверьте, что в Vercel выбран этот каталог проекта, а команды сборки и запуска не переопределяют настройки Next.js. Для локальной проверки выполните `npm ci`, `npm run lint`, `npm run typecheck` и `npm run build`.

Подключённая Turso выбрана пользователем как production-база. Для Preview и разработки нужна отдельная база. Применяйте миграции только к заранее проверенной базе и создавайте резервную копию перед изменением существующей базы. Настройте [резервное копирование и восстановление](backup-guide.md).

## Переменные окружения

Значения задаются через настройки проекта Vercel для каждого окружения. Не помещайте ключи в репозиторий, URL, логи или переписку.

| Переменная | Что указать |
|---|---|
| `TURSO_DATABASE_URL` | URL соответствующей базы Turso. |
| `TURSO_AUTH_TOKEN` | Токен для этой базы. |
| `BETTER_AUTH_SECRET` | Отдельный случайный секрет не короче 32 символов. |
| `BETTER_AUTH_URL` | Точный HTTPS-адрес приложения в данном окружении, без завершающего `/`. |
| `RESEND_API_KEY` | Ключ Resend для отправки писем. |
| `EMAIL_FROM` | Подтверждённый отправитель, например `Salary <noreply@ваш-домен>`. |
| `SALARY_CLIENT_IP_HEADER` | `x-real-ip` при прямом использовании Vercel, после проверки конфигурации прокси. |

Vercel документирует `x-real-ip` как адрес клиента, аналогичный `x-forwarded-for`; при использовании дополнительных прокси или собственной Enterprise-конфигурации необходимо отдельно проверить, какой адрес будет виден и можно ли подделать заголовок. Не открывайте сервер приложения в обход доверенного прокси. Без этой переменной действует общий ограничитель для пользователей одного маршрута. [Документация заголовков Vercel](https://vercel.com/docs/headers/request-headers).

Не используйте production-базу и production-ключи в Preview. Настройте для Preview отдельную базу, отдельный секрет и проверенный адрес Preview; `BETTER_AUTH_URL` должен совпадать с адресом, на котором проверяется авторизация и восстановление пароля. Не запускайте тестовые скрипты, создающие аккаунты, в production.

## Порядок запуска

1. Проект `salary` уже создан в аккаунте Vercel и связан с локальной папкой через CLI. Служебный каталог `.vercel/` исключён из Git; `.vercelignore` исключает переменные и локальные базы из загрузки. [Инструкция Vercel](https://vercel.com/docs/projects/deploy-from-cli).
2. Указать переменные для Preview и проверить отдельную базу. Создать предварительное размещение и проверить регистрацию, вход, операции, аналитику и изоляцию двух тестовых аккаунтов.
3. Подключить Resend и отправить письмо на принадлежащий проверяющему адрес. Проверить ссылку, новый пароль, невозможность повторного использования ссылки и отзыв старых сессий.
4. Настроить мониторинг `/api/health`, проверить резервную копию и восстановление в отдельной базе, проверить внешний вид и навигацию с клавиатуры на телефоне и компьютере.
5. Задать production-переменные, выполнить production-размещение и повторить безопасные проверки. Продакшен-адрес и секреты нельзя считать настроенными до фактической проверки.

`vercel env pull .env.local` может перезаписать локальные настройки. Не выполняйте её поверх существующего `.env.local` без резервной копии и проверки цели.

Сейчас Vercel-проект создан и связан с локальной папкой. В Production добавлены URL и токен выбранной Turso, новый отдельный `BETTER_AUTH_SECRET` и `SALARY_CLIENT_IP_HEADER=x-real-ip`. Значения сохранены как скрытые переменные. `BETTER_AUTH_URL`, Resend, Preview, публикация и проверка настроек на Vercel ещё не выполнены. В инструментах разработки остаются замечания `npm audit`; production-зависимости на последней проверке не содержали обнаруженных уязвимостей.
